# AGENTS.md

GUI-only PyQt6 PDF reader (console version was removed). Educational/experimental project.

## Run the app
Use the helper scripts from the repo root (they pick the `pdf-reader-clean` env python and `gui_app/` working dir automatically):

```powershell
.\run.ps1   # run once
.\dev.ps1   # watch gui_app/**/*.py and auto-restart on save
```

Manual equivalent (imports are flat, not `gui_app.`-prefixed, so run from `gui_app/`):

```powershell
cd pdf_reader/gui_app
python main.py
```

- Environment python: `D:\volume\tempprograms\anaconda\envs\pdf-reader-clean\python.exe` (conda env `pdf-reader-clean`).
- Dependencies: `PyQt6` + `pymupdf`, declared in `requirements.txt` (repo root). A fresh environment will fail to import until deps are installed (e.g. `pip install -r requirements.txt`).
- Image/PDF lib is imported as `pymupdf` in the GUI code, not `fitz` (though `services/*` loader/detector still use `fitz`).
- Perf logging (opt-in, #87-#89): set `$env:PDFR_DEBUG_PERF="1"` (any truthy value) or create the marker file `pdf_reader/gui_app/perf.enabled`; `run.ps1` echoes ON/OFF at launch, every line goes to stdout AND appends to `gui_app/perf.log` (both gitignored), including the perceived-latency mark `back: click -> library first paint`. Delete the marker to disable.

## Structure
- `gui_app/main.py` — entry point. `main_window.py` holds `MainWindow` (sidebar + view stack).
- `gui_app/views/` — screens: `library_view.py` (PDF list with per-row checkboxes, ✅ Select all / 🗑️ Remove Selected / Del (#72), and the 💾 Backup button that snapshots `library.db` into `backups/` via `backup_database` (#83)), `pdf_reader_view.py` (core reader), `extracts_view.py` (Document→Extract review + edit + delete, one row per Extract; the full-area Extract Editor; `open_extract(doc_id, extract_id)` — the landing target for flashcard source jumps, #62), plus `flashcards_view.py` (card list with ✏️ Edit question / 🗑 Delete row actions — F2/Del shortcuts, confirmed delete, edit preserves `fsrs_json`/`due_utc` (#60) — the header's checkable 📅 Due today filter that shows exactly the Review session's set via `_due_cards` (#61) — the source column's click-to-jump (`source_jump_requested(doc_id, extract_id)` → MainWindow → `extracts_view.open_extract`; `⚠ source gone` / `(source gone)` label when the source row is gone, jump hidden, #62) — and `ReviewSessionDialog`: Review (n) button, Space reveal, keys 1-4 grade through FSRS, Again re-queues once within a fixed total, end-of-session summary + Close, empty-day `due_hint`, #58/#59).
- `gui_app/services/` — headless seams `extract_store.py` (extract/capture/flashcard SQL — orphan-aware `list_flashcards`/`list_due_cards` + `extract_exists` liveness probe, `delete_extract` never cascades to flashcards (#62) — plus `backup_database` — sqlite3 `backup()`-API snapshot into `backups/`, pruned to newest 10 by mtime, no Qt, #83), `pdf_geometry.py` (Qt-mirroring layout math), `selection_snapshot.py` (editor selection → answer snapshot, offscreen Qt), and `fsrs_scheduler.py` (thin wrapper over the pinned `fsrs` lib — `rate_card`, `end_of_local_day_utc`, fuzz on in app / off in tests, no Qt, #58), and `perf_log.py` (opt-in timing — env/marker switch → console + `perf.log`, `span`/`mark`/`log_since` probes incl. the Back click→paint latency, #87-#89); plus the live `element_detector.py` (image click-capture). `views/flashcard_answer.py` is the shared U+FFFC answer renderer (used by the Make-flashcard dialog and the review session).
- `gui_app/tests/` — pytest suite for the seams (flat imports via `conftest.py`).

## Gotchas
- `services/` files use package-relative imports (`from .element_detector ...`); it has an `__init__.py`. If you activate them, import via the package, not as scripts. (`extract_store.py` and `pdf_geometry.py` are flat — imported as `services.extract_store` from the app/tests.)
- `gui_app/library.db` (per-file read progress), `gui_app/backups/` (the 💾 Backup button's `library-*.db` snapshots, #83), `__pycache__/`, and the perf-logging artifacts `gui_app/perf.log` + `gui_app/perf.enabled` are gitignored (`*.db` covers the backup copies).
- `gui_app/views/pdf_reader_view.py:26-28` inserts the repo root into `sys.path` — cargo-culted; not actively required by anything.
- Extracts schema (blob model): `extracts(id, doc_id, created_at, type, text_content, doc_name)` + `captures(id, extract_id, page, rect 'x0,y0,x1,y1' - both nullable, NULL for pasted images #48, kind, text_content, image_blob, display_w, display_order)` — the Extract's text is ONE blob in `text_content` (inline images marked U+FFFC, one per image Capture in capture order); captures are immutable anchors (their `text_content` is always NULL; `display_w`/`display_order` are presentation-only — inline-image resize width (#37) and capture order in the blob: text anchors first, then images in document order (#48)) used for blue redraw + Jump. The reader draws persisted extracts blue on load and keeps a transient yellow Working Set; commiting (`e`) turns the Working Set into one Extract row (blob joined blank-line-separated, placeholders per image); `d`-twice deletes the newest Extract on the current page; the Extracts View (Document→Extract, one row per Extract) reviews and edits (the full-area Extract Editor: ONE joined `_ExtractDocEdit` per Extract with inline images - including clipboard image pastes (#48: stored on save as page/rect-NULL captures) - 💾 Save + Back auto-save through `save_extract_text` (legacy text-only path returns `True`; with image backends it returns the created paste ids or `False`) which strips unbacked placeholders — a deleted placeholder stays deleted, empties allowed) and deletes with a confirmation popup. `capture_overlaps_extract` / `delete_extract` / `save_extract_text` live in the seam; `init_schema` is idempotent AND migrates older DBs once (backfills the blob from legacy per-capture text then NULLs it; atomically rewrites `captures` for nullable `page`/`rect` + `display_order`, #48; adds/backfills `extracts.doc_name`, the Document display-title snapshot so a removed source keeps its name, #70). Flashcards (#54/#55): `flashcards(id, extract_id, doc_id, question, answer_text, created_at, fsrs_json, due_utc)` + `flashcard_images` (blobs written at creation, #56) + `review_logs` (rating table written from #58); the answer is an immutable editor-selection snapshot (`services/selection_snapshot.py`), cards survive source removal (LEFT JOIN source name, `extracts.doc_name` fallback #70), `due_utc` defaults to now (fresh card due immediately), `fsrs_json` was NULL until the FSRS scheduler landed (#58); `extract_exists` is the card→source liveness probe backing the jump/label logic (#62); `update_flashcard_question` / `delete_flashcard` (also deletes the card's image/log children explicitly — the FK pragma stays off) live in the seam.
- **Surface every shortcut in the menu** (user convention, after #57): when a feature ships a keyboard shortcut, set it on the matching menu action (`QAction.setShortcut`) so Qt prints the combo beside the label (there is no `QMenu.setShortcutVisible` in Qt 6.11 — display follows the style hint, on for Fusion), and list the combo in `HOW_TO_USE.md`'s cheat sheet.

## Workflow (user expectation)
- **Commit and push after every change** — the user does not want to be reminded. Feature work goes on feature branches → PR → review → merge to `master`. Doc-only changes go straight to `master`, and `AGENTS.md` itself is edited directly on `master` (self-referential doc).
- **Always end a shipped feature with a visual checklist** (user convention, after #60, style fixed after #61): hand the user a Markdown **bullet list** (`- [ ]` items) of manual, on-screen checks before merging — run via `run.ps1` on the branch. ELI5 style: one short action per item ("Click 📅 Due today — the tomorrow row disappears"), no nested parentheses, no essay sentences; group under short bold headings (toggle/happy path, cancel path, keyboard path, empty state, no-regression). Tests gate the code; the checklist gates the merge.
